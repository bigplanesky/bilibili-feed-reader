# 实现说明

当前版本：1.0.2。

无需构建、安装依赖或访问外部服务，整个扩展由本地 JavaScript、CSS 和 Manifest 组成。

## 结构

- `core.js`：ID 和时间校验、默认设置、可见性规则、整批时间边界判断。
- `background.js`：Manifest V3 service worker，按接收顺序处理状态和设置请求。
- `bridge.js`：随扩展打包的 MAIN world 脚本，只从外层动态 Vue 组件提取 ID、发布时间和置顶标识。
- `adapter.js`：B 站 DOM 适配、评论展开与就绪判断、原生分页加载区域适配。
- `content.js` / `content.css`：卡片标记、工具栏、当前页面已读保留、分页调度。

状态按钮使用作者栏下方的独立同级容器，不插入 B 站固定高度的作者栏。捕获 `click` 和 `auxclick` 中的内容入口操作并保存外层动态已读；不阻止或替换网站的原始跳转。仅将 B 站视频、动态详情、图文详情及专栏链接识别为内容链接，普通作者／话题／商城链接不触发。时间和图文正文是已核实的无 href 详情入口；右键菜单打开尚不识别。

已读卡片通过已有的 `data-bfr-status="read"` 属性应用淡绿色底色。改回未读、存储失败回滚、多标签页同步和节点复用均沿用原有状态更新，CSS 随状态自动恢复；不覆盖未读卡片的原始背景。

## 存储与消息

只申请 `storage` 权限，content scripts 仅匹配 `https://t.bilibili.com/*`。没有远程代码、Cookie 权限、网络拦截或跨站请求。

存储键：

```text
bfr.settings = { hideRead: boolean, days: 0 | 7 | 30 | 90 }
bfr.read.<动态ID字符串> = { readAt: 毫秒时间戳, publishedAt: 秒时间戳 | null }
```

每个动态独立写键，避免不同标签页同时保存整个列表导致记录丢失。Worker 将写入和初始读取串行化，设置只按字段合并。卡片和其他标签页通过 `chrome.storage.onChanged` 更新状态。

内部消息类型：`BFR_GET_STATE`、`BFR_SET_READ`、`BFR_SET_SETTINGS`。只接受来自动态站点标签页的消息；不暴露外部消息接口。

页面桥接只传递有限长度的 JSON 字符串。传入 ID 始终重新校验，超过安全整数范围的数字型 ID 会拒绝，字符串型大 ID 保留全部数字；不使用视频 ID 或原动态 ID 代替外层动态 ID。

## 分页策略

在筛选造成空白且页面在前台时，串行触发原生加载区域，等待卡片集合变化，不另外请求动态 API。每批等待最多 12 秒、每轮最多 10 批；隐藏加载哨兵以暂停连续预取，继续时恢复。

仅完整的新普通动态批次全部可识别、可确定发布时间且均超出时间范围时，将其视为时间边界。未知卡片和单条旧置顶不会形成这个边界。B 站提供的排序和流内容仍决定能浏览到哪些动态。

## 适配限制

已在登录态 Edge 动态页抽查独立状态行、打开视频后的源动态已读与刷新持久化；这不代表所有动态类型和分页情况均已在真实页面验收。详见《验证结果.md》。B 站组件字段、评论 Shadow DOM 或分页结构改变时，主要在 `adapter.js` 和 `bridge.js` 更新适配。识别失败时默认保留动态，分页无进展时暂停并给出重试按钮。
